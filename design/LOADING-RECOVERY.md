## State contract

- Loading uses neutral skeletons and a labelled loading state, not fake listings/counts. Keep layout geometry stable and expose one concise accessible status. Skeletons are decorative/noninteractive; avoid flashing/shimmer or respect reduced motion. Transition to real result, genuine empty or error, never wait indefinitely without recovery.
- Empty marketplace means the unfiltered authorised query succeeded with no visible listings. It is distinct from a filtered zero-result query or failed load. Publish entry can require sign-in without silently submitting a listing.
- Zero-result search preserves query and active facets. Clear all filters removes facets, retaining the typed query and applying the existing sort contract. Edit search focuses the query. Both actions update the existing shareable URL state; no saved search, notifications, history tracking, suggested inventory or AI/fuzzy search was added. The Desk lamp / Under €10 / Innenstadt example has two facets and zero results, not a live search.
- Failed initial load preserves query/facets and retries the same read. Do not claim an empty marketplace on an error. Offline is a conditional connectivity hint after a failed request and corroborating state, not a diagnosis derived from HTTP failures alone. Reconnect/retry remains available. No persistent offline browsing, service worker, background upload, PWA or native capability is introduced.
- Pagination failure preserves the confirmed current list and cursor, retrying only the failed next read without duplicates or cursor advancement on failure. On auth/block changes, reauthorise and invalidate prohibited data rather than treating an old view as an offline cache.
- Unavailable listing uses a neutral public result consistent with the existing not-found contract. Do not distinguish nonexistent, removed, unauthorised or mutually blocked targets through copy, target identity or extra metadata. Back to results is offered only when a valid prior result context exists; otherwise prefer Browse marketplace. Preserve a safe return URL without exposing protected content.
- A failed cover-photo fetch displays Photo couldn’t load and retry; it does not replace the actual listing photo with unrelated stock. A Wanted listing with no image deliberately displays its request placeholder and has no failed-image retry. New Wanted lamp placeholders use a generic seeking icon, not an unrelated category/book symbol. Fixtures use the existing chair/books prototype assets only, not live seller inventory. Their prices/areas are fictional; no wardrobe is represented by a chair photo.

## Forms and photos

Partial upload example has two acknowledged uploads and one failed file, not a successfully published listing. Retry targets only the failed file; Remove failed photo removes that selection while retaining the acknowledged photos in this form. Continue is disabled until selected files are resolved and the listing-type image rules hold. SELL/GIVE_AWAY still need 1–8 confirmed images; WANTED may have 0–8. Retry must re-check authoritative upload state/expiry rather than duplicate records. Required-image failures cannot result in a partially created public listing; existing atomic submission and orphan cleanup apply. File names are fixtures, not evidence of real uploads.

Photo feedback preserves JPEG/PNG/WebP and 5 MB limits. The sample smaller-photo message applies to a size rejection; unsupported format needs its own accurate reason, not a misleading size error. Keep retry/remove targets keyboard operable and at least 44 px interaction areas even when the label itself is smaller. Announce progress without repeatedly reading filenames/statuses. Cover/reorder/remaining image cases still use page 07's gallery contract.

Unsaved confirmation is contextual to a dirty profile form: Keep editing is primary and returns focus to the form; Discard changes navigates to the intended safe destination without applying the edit. The sample Maya S. change is unsaved, not a server draft or auto-save. Internal navigation can show this sheet/dialog; browser close/reload uses the browser's supported native unload behavior, not a promise of custom close interception. Don't prompt on pristine or acknowledged-saved forms. Preserve editable values while staying on the page, but don't promise survival across reload/close without an approved persistence contract.

Invalid-profile example starts with an empty name and placeholder. Its inline error applies the existing trimmed 2–50 character contract, with the existing control/markup restrictions unchanged. Focus/associate the error with the field; do not show a successful save or replace the confirmed profile on rejection. Private edit/upload desktop views use the member navigation rather than a guest header.

The feedback board separates saving, acknowledged success, confirmed failure and uncertain save result. Prevent duplicate submissions without trapping focus. On uncertain outcomes preserve the local draft, query the current record/status and reconcile before retrying; do not assert the change never happened. A stale listing requires refreshing its actual state before an offer; server interaction gates remain authoritative. Authentication returns to the intended action but does not automatically submit. Rate-limit recovery uses actual endpoint eligibility/timing, not an invented countdown.
